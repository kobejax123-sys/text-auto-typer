# 文本自动输入器

Windows 上的按键映射工具：给每个热键绑定一段文本，之后在任何输入框里按下该热键，
文本会被粘贴进去。参考「楼月文本自动输入器」的交互。

纯 Python 标准库实现（tkinter + ctypes），不需要安装任何第三方包。

## 文件

| 文件 | 说明 |
| --- | --- |
| `winapi.py` | Win32 封装：全局低级键盘钩子、剪贴板读写、Ctrl+V 粘贴、系统托盘 |
| `main.py` | 图形界面与主程序 |
| `selftest.py` | 自测脚本，验证结构体布局、键码解析、钩子安装、剪贴板与粘贴 |
| `make_ico.py` | 把多尺寸 PNG 打包成 .ico 的小工具 |
| `app.ico` | 程序图标，窗口、任务栏和桌面快捷方式都用它 |
| `icons/` | 候选图标与各尺寸 PNG 源文件 |

## 运行

日常用桌面上的「文本自动输入器」快捷方式，它直接以**普通权限**启动程序，启动后常驻托盘。
需要往管理员权限的程序（如 IP Scanner）里粘贴时，从托盘右键「以管理员身份重启」提权一次，
原因和做法见「管理员权限（按需提权）」。

开发或临时试用时也可以直接跑：

```bash
python main.py
```

程序同一时间只允许跑一个实例。重复启动时，新实例会立即退出（退出码 1）并把已有窗口叫到前台，
即使那个窗口正藏在托盘里——否则两个实例各装一个键盘钩子会互相抢按键。

## 用法

1. 点「添加」，在弹出的窗口里点「按下按键…」，按下想用的键（如 `F2`），再填要输入的文本。
   把字母、数字、空格这类打字常用的键设为热键时会弹窗二次确认——它们会被本程序全局吞掉，
   正常打字就打不出这个字符了。
2. 之后在任意输入框按该热键，文本被粘贴进去。
3. **双击**表格任意一行，可把该行文本复制到剪贴板。
4. 临时想让出这些按键时，在「设置」菜单里取消勾选「启用热键」。
5. 关闭窗口默认**最小化到托盘**，程序继续在后台响应热键。双击托盘图标可重新打开窗口，
   右键托盘图标有「显示主窗口」和「退出」。
6. 想让关闭窗口就等于退出，在「设置 → 关闭窗口时」里改成「直接退出程序」，这个选择会记住。
7. 「设置 → 开机自启」开关的是一个登录计划任务：登录时静默提权、待在托盘，从此一次 UAC
   都不用点。开和关都需要程序处于管理员权限（普通权限下勾选会提示先提权）。

配置保存在 `%APPDATA%\TextAutoTyper\config.json`，菜单「文件 → 打开配置文件位置」可直接打开该目录。

## 管理员权限（按需提权）

Windows 的 UIPI（用户界面特权隔离）规定：普通权限的进程**不能**向管理员权限的进程发送输入，
`SendInput` 注入的按键会被系统直接丢弃。所以往 IP Scanner 这类以管理员运行的程序里粘贴时，
本程序也得是管理员权限。

为此托盘右键菜单里有「以管理员身份重启」：点一下、在 UAC 上确认，程序便以最高权限重启，
热键和配置都原样保留。平时保持普通权限就好——往浏览器、企业微信这些普通权限程序粘贴
用不着提权，高权限向低权限发送输入本来就是允许的。被 UIPI 拦下时状态栏会提示
「目标窗口是管理员权限」，不至于按了热键没反应还以为程序坏了。

以管理员身份运行期间：普通权限的终端杀不掉这个进程（`Stop-Process` 会报「拒绝访问」），
退出走托盘右键；托盘菜单里也不再显示「以管理员身份重启」。

## 为什么要按需提权，而不是一直管理员

程序以前靠一个最高权限的计划任务启动（免 UAC），但那条启动链脱离了用户的输入 lineage：
拉起进程的是任务计划服务而不是收到你双击的资源管理器，Windows 的前台权限链里没有它，
只能用 `AttachThreadInput` 强抢前台。强抢撞上「刚退出、前台回落到桌面」的过渡态时，
偶发窗口被插进 Z 序的异常位置——任务栏和托盘里都有它，桌面上却没有，得 Alt+Tab 才唤得出来。
改成普通权限直接启动后，程序天生在权限链里，窗口正常申请前台即可，
这整类毛病从根上消失，强抢代码也随之删除。

## 实现要点

- **热键**：用 `WH_KEYBOARD_LL` 低级键盘钩子全局拦截，钩子跑在独立线程自己的消息循环里，
  主线程通过队列取事件——低级钩子回调阻塞超过 300ms 会被系统静默摘掉，所以回调里只做查表和入队。
- **粘贴**：把文本以 `CF_UNICODETEXT` 写进剪贴板，再用 `SendInput` 发一次 `Ctrl+V`。
  比模拟键盘逐字输入快得多，也不受字符集限制（中文、emoji、换行都能原样过去）。
  剪贴板同一时刻只允许一个进程打开，被占用时重试几次。写入时先分配好内存、填好数据，
  最后才 `EmptyClipboard`——反过来做的话，清空之后才失败，用户原来复制的内容就没了。
- **还原剪贴板**：粘贴前先记下原来的文本，300ms 后放回去——目标程序是异步读剪贴板的，
  恢复太早会读到旧内容。恢复前还会确认剪贴板里仍是本次写入的内容，
  免得覆盖用户这期间新复制的东西。
- **防递归**：注入的按键带 `LLKHF_INJECTED` 标志，钩子识别后直接放行，所以文本里出现热键字符也不会自我触发。
- **自动重复**：按住热键不放只触发一次，靠跟踪按键按下状态实现。
- **托盘**：`Shell_NotifyIcon` 加图标，通过子类化 Tk 窗口的窗口过程来接收托盘消息
  （`WM_APP+1`，鼠标事件在 `lParam` 的低字里）。所以托盘菜单的回调直接在 Tk 主线程执行，
  不需要跨线程通信；退出时会把原来的窗口过程还原回去。弹菜单前先把窗口设为前台、
  关掉后补一条 `WM_NULL`（文档要求的收尾），否则菜单点了别处可能留在屏幕上不消失。
  托盘图标建不出来时，「关闭窗口时」会降级为直接退出并把那个菜单项置灰——没有图标就没办法
  把窗口叫回来，收起来等于让用户找不回它，而进程还在后台吞着热键。降级只改运行时状态，
  不写回配置，所以下次托盘正常时用户原来的选择还在。
- **单实例**：启动时抢一个命名互斥体（`CreateMutexW`）。已经有了就直接退出，并按窗口标题
  找到已有实例的窗口叫到前台。两个实例会各装一个键盘钩子互相抢按键，必须拦住。
  对方权限更高时互斥体打不开（`ERROR_ACCESS_DENIED`），这种情况同样按「已有实例」处理。
- **开机自启（提权）**：开机要静默拿到管理员权限，Run 键和启动文件夹都做不到（Vista 起
  就禁了它们提权），唯一正路是登录计划任务（`RunLevel Highest`）——UAC 的同意前置到建任务
  这一刻。任务 XML 由程序自己生成、`schtasks /create /xml` 建出来；状态只看 `/query` 的
  返回码、不解析输出，避开 schtasks 的 GBK 编码和本地化文本的坑。开和关都要本程序处于
  管理员权限。桌面快捷方式仍是普通权限启动：双击时新实例留下 `show.flag` 信号就退出，
  托盘里的管理员实例轮询到信号后自己亮出窗口——普通进程没法操作管理员实例的窗口（UIPI），
  只能递话。
- **按需提权**：托盘右键「以管理员身份重启」用 `ShellExecuteW` 的 runas 动词拉起一个
  提权的新实例（带 `--restart`），本实例随即退出。新实例轮询等互斥体放开再启动，避免撞车；
  判断当前是否已提权查的是进程令牌的 `TokenElevation`，而不是猜。粘贴失败时若发现目标窗口
  属主是提权进程而自己不是，状态栏提示从托盘提权——`SendInput` 被 UIPI 拦时只返回 0，
  错误码不可靠（文档明说看不出来），只能自己查令牌。开机自启的任务建成后，登录起就
  常驻管理员权限，日常连这一下 UAC 都省了。
- **静默启动**：`main.py --tray` 只装钩子、建托盘，不弹窗口也不抢前台，供登录自启使用。
  窗口位置在隐藏状态下就已经量好摆好了，用户点托盘图标唤出来时直接是居中的。
- **启动日志**：`%APPDATA%\TextAutoTyper\startup.log` 记流水——每次启动、退出。这类毛病
  偶发又难复现，事后只能靠这串记录还原现场。超过 256KB 自动重建，写不进去就静默跳过，
  绝不会因为它影响程序本身。
- **窗口位置**：打开时按主屏的工作区（即去掉任务栏之后的范围）居中。这里有两个坑：
  `wm geometry` 的 `+x+y` 定位的是窗口**外框**，而 `WxH` 是**客户区**尺寸，两个坐标系不同，
  得先把边框和标题栏量出来补掉，直接拿客户区尺寸算会偏几十像素；而窗口还没映射时
  `winfo_rootx/y` 给的又是没意义的数字，所以要先把它摆到 `+0+0` 再量。另外整个构建过程在
  `withdraw` 状态下进行，等位置算好了才 `deiconify`，免得看见窗口从系统给的默认位置跳到中间。
  分辨率、DPI 缩放、任务栏在哪条边（左/上时工作区左上角不是原点）都靠运行时测量，没有写死像素；
  只有工作区小到装不下窗口时（例如 1080p 开 300% 缩放）居中的坐标会是负数，那种情况退回贴着左上角。
- **配置容错**：两种读失败分开处理。内容是**坏的**（JSON 解析不了、编码错乱）才把它改名成
  `config.json.bak` 再以空配置启动，否则每次启动都报同一个错、用户也不知道该删哪个文件；
  只是**读不到**（被杀软扫描、同步盘锁住、权限不足）则原样留着文件、只弹窗告知。
  这类错误重启一次多半就好了，要是也按损坏处理，等于把可恢复的配置白白搬走。

## 已知限制

- 只支持**单键**热键（`F1`~`F24`、字母、数字、小键盘、方向键等），不支持 `Ctrl+F2` 这类组合键。
- 被设为热键的按键不会再传给其他程序。把 `F1` 设为热键后，其他软件的 F1 帮助功能会失效。
- 粘贴会临时占用剪贴板。原来里面是**文本**的话会自动还原；如果是图片、文件等非文本内容，
  就无法还原了，只会留下这次粘贴的文本。
- 极少数屏蔽 `Ctrl+V` 的输入框（部分网银、安全控件）粘贴不进去。
- 目标程序若以管理员身份运行，本程序也得提权（托盘右键「以管理员身份重启」），否则按键
  会被系统丢弃，表现为按了热键但目标里什么都没有，状态栏会有提示。详见「管理员权限」。
- 文本框只支持单行文本，不能绑定含换行的内容。

## 自测

```bash
python selftest.py
```

依次检查结构体布局、键码解析、键盘钩子能否安装、剪贴板读写，然后短暂弹出一个窗口，
自动往里面粘贴短文本和 160 字符的长文本并核对结果。全部通过时退出码为 0。
测试期间会临时占用剪贴板，原本是文本的话结束后会还原。

两个踩过的坑，写在这里免得重蹈覆辙：

- 断言前要**轮询等目标程序消化**。`SendInput` 返回时按键只是进了系统输入队列，
  实测 Tk 消化 160 个字符约 0.5 秒，立刻读会误判成"丢字符"。
- 自测里必须用 `AttachThreadInput` 把窗口**强行**切到前台。Windows 有前台锁定，
  后台进程调 `SetForegroundWindow` 会被拒绝，焦点会留在任务栏，注入的按键就打到了别处。
  生产代码只在**启动时**用一次（见「实现要点 → 启动时抢前台」），粘贴时不需要——按热键
  那会儿用户正在用的窗口本来就是前台。

## 图标

`app.ico` 用的是 [Icons8](https://icons8.com) Fluency 风格的键盘图标（免费使用需署名）。
`icons/` 里另存了两个候选（`paste.ico` 粘贴板、`lightning-bolt.ico` 闪电）以及各尺寸 PNG 源文件。
换图标：把选中的那个复制成 `app.ico`，再更新桌面快捷方式的图标位置即可。

想拿自己的图做 ico，准备好几档尺寸的 PNG 后：

```bash
python make_ico.py 输出.ico 16.png 32.png 48.png 64.png 128.png 256.png
```

尺寸给得越全，图标在标题栏、任务栏、大图标视图下越清晰。

```bash
pip install pyinstaller

```
